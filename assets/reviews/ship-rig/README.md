# National ensigns and radar articulation

The registered fleet's versioned blueprints own flag design, hoist placement, dimensions and radar joint bindings. Original flag artwork and historical references are in [the source register](../../parts/ensigns-sources.md). New staff geometry is generated by `scripts/ships/blender_rig.py`; independent moving aerials and directors stay under stable pivot IDs. Existing staff or mast geometry is reused for Bismarck, Yamato, King George V, Enterprise and Fletcher. King George V's old rigid flag geometry is replaced by the shared cloth.

The local Blender pipeline was used; no Blender MCP connection was available. Shared recipe and schema changes require rebuilding every registered asset. Fixed source views are under each ship's `generated/review/`; those show staffs and sensor geometry. Cloth exists in the game renderer, so runtime captures complement those views.

Open `/scripts/diagnostics/ship-rig.html?ship=yamato` in the development server for the actual ocean scene with a close flag camera. `reviewRig('flag', windMps, shipMps)` changes apparent airflow; `reviewRig('radar')` frames a sensor. Await `advanceRig(seconds)` to run controlled frames and hold the result for screenshots, including in a background tab. `shipTrialDiagnostics().shipRigs` in the ordinary development game exposes the selected flag design, visible state, cloth tip and radar angle without changing combat.

Physics covers pinned hoists, gravity in the ship frame, pressure and skin drag, relative ship translation/yaw, bounded gusts, structural/shear/bend constraints and a fixed timestep. CPU combat poses and weapon joints remain authoritative. Fabric does not collide with rigging or itself, tear or get wet; distant subpixel flags hold their latest fold. Radar sector/rate calibration, flag dimensions, hoist locations and always-hoisted etiquette remain approximations in each discrepancy register. Ensign colors identify ship nationality, independently of battle team.


Integration validation completed 2026-09-07 against master `f3820a54`, using local Blender 5.2.0 LTS and the actual ocean renderer in Orca's embedded browser. The fleet retains master's equipment support and anti-aircraft repairs. Earlier captures are preserved under [pre-integration](pre-integration/README.md), grouped by their original model hashes.

- Every registered ship was rebuilt with `ship:build`, passed `ship:check`, and had its current `ship:review` fixed views inspected.
- `bun run test`: all 102 test files passed with zero failed files. This includes simulation, renderer, asset integration, and the new cloth/rig tests.
- `bun run build` passed fleet and aircraft checks, TypeScript and the production bundle.
- In-game verification checks changing cloth positions and fitted radar angles, pause preservation, and three weapon train positions with elevation and recoil. Each motion report records the exact loaded model hash; captures hold the tested simulation frame.

All fleet motion checks passed. Maximum measured weapon muzzle discrepancy was 0.002746 m. [Validation record](validation.json).
