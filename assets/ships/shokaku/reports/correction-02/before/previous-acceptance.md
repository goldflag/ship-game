# Shōkaku — model and runtime review

The December 1941 reconstruction is playable in the harbor and Custom battle. Attachment, exposed mechanisms and permitted movement pass the reviews below. Historical proportions remain **qualified**, with unresolved source provenance and local dimensions explicitly retained in [SK01–SK06](discrepancies.md). This is not a claim of 100% historical accuracy.

Reviewed ship: `shokaku`. Exact content hash:
`16bd50f50408f1a02ed6a0635aaa585a7ae182000b30de6bb7b4ffe5146ef890`.

The [export report](export.json) records 327,052 triangles, 181 meshes, 393 primitives and 11,472,096 bytes. The generated Blender scene, compiled definition and GLB carry the same hash. Geometry originates in the version-1 blueprint, original ship recipe and original four-variant Japanese gun recipe. Reference scans were used as evidence, never as production meshes or textures. The tool actually used was **local Blender 5.2.0 LTS**; Blender MCP was not exposed.

## Actual game verification

Evidence was collected from the real development `Game` and loaded GLB in Chrome 152.0.7977.83 with the **WebGPU** renderer. Orca's background tab repeatedly closed during long checks; an isolated headless Chrome instance completed the review. Development fixtures can advance bounded fixed CPU ticks and place controlled targets. Their overrides are stated in each record. They do not alter shipped definitions, hit points or flooding to manufacture damage results.

## Validation and reproduction

`bun run test` passes **892 tests across 124 files**, with zero failures. `bun run build` passes all ship and aircraft asset checks, TypeScript and production bundling. Shared compiler changes required rebuilding stale fleet outputs; existing ship authoring inputs and Bismarck's baseline were preserved. The shared preload chunk exceeds Vite's configured 7,000 kB warning threshold; the build succeeds.

See [validation metadata](validation.json), [test output](tests.log), [build output](build.log) and [review instructions](../authoring/README.md). Any future geometry change needs a new build and affected reviews under its new exact hash. Earlier hash folders are retained as historical records only.
